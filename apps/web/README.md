# Knowledge Engine web interface

The active frontend uses HTML, CSS, and browser JavaScript modules. FastAPI serves `index.html` at `/` and assets under `/static`; no npm installation or build is required.

Screens: Home, Library and material details, Create with an optional idea picker, My work and revision/history, and Settings. The brand returns to Home. Hash URLs restore the current view and library/material scope on refresh and browser Back/Forward; an empty or invalid route starts at Home. Unsaved Create fields (including format and creator direction) and selected ideas survive navigation within the tab, but are not persisted across a full refresh or tab closure. Draft text is never written to the URL or browser storage. The shared `api()` helper handles JSON, uploads, and readable API failures. All source/model text is inserted with `textContent`, not interpreted as HTML.

Run the project with `bash scripts/run.sh` from the repository root. Seed original sample material with `.venv/bin/python scripts/seed_demo.py` while the app runs.

Accessibility provisions include semantic controls, nested labels, a skip link, live status feedback, progress labels, busy state, focus outlines, and responsive CSS. These still need an actual browser/mobile acceptance pass; they are not an accessibility certification. Use `docs/beta_test_checklist.md` to record that review.

Local mode remains accessible without a password. Hosted mode uses one shared private-beta password and signed browser sessions; the login page needs only the shared stylesheet. The shared `api.js` transport adds session-bound CSRF headers to unsafe same-origin requests, including the enhancement layer, with complete Create payloads supplied by the interaction adapter. A POST Sign out action clears browser cookies. Manual JSON import is an advanced path; ordinary AI processing and saved-output revision use forms.

Frontend tests: `node --test --test-isolation=none apps/web/tests/*.test.mjs` from the repository root. All request tests use mocks.


Create now starts with one natural request. `interaction-draft.js` owns presentation state and the single Workshop adapter; `app.js` displays/edit-confirms it. Continue organizes the request locally and retrieves prepared knowledge without an AI call. The default confirmation shows concise intent, populated instructions and source coverage. Empty optional details and developer import are concealed. The result-specific Create action saves using the exact server-owned knowledge snapshot shown in the preview. Search scope identifies where retrieval is allowed. On small screens, two ideas are initially visible with a View all control; every retrieved idea remains in the prepared snapshot. A changed draft invalidates it; committed detail/scope edits prepare automatically, and typing never makes a provider call. Request text and corrections survive tab navigation, not full refresh. Output format and creator direction are part of the adapter rather than fetch wrappers. See `docs/create_interaction_acceptance.md` for verification and review scenarios.
